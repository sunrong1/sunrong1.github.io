# 一人成军：《算法大赛》的 AI Agent 协作心法（6 大反直觉 + 1 句核心）


> 听了一场**《算法大赛》的复盘分享**。**全程没有炫技，没有参数数字，只有一个问题反复回响：**
> **"人，在 AI 时代，到底该把精力放在哪里？"**
> **6 个观点，没有一个是我在 AgentScope 源码里读到的——全部是 73 个会话 + 4 个模型群聊 + 2 轮比赛砸出来的。**

***

<!-- more -->

## 📌 演讲核心一句话

> **未来研发 = 一个人带着一支 AI 队伍。**
> **模型会换，最贵的永远是"知道该对哪一个答案不满意"。**

这句话我看完就抄进自己的 `myblog.md` 顶部了——**因为它回答了一个困扰我 8 周的问题**：

> **"读 AgentScope 源码 15600+ 行，到底学什么？"**

**答案**——**不是学 agent 的实现**——**是学"人怎么管一群 agent"**。

下面 6 个观点，对应这场分享的 6 块肌肉记忆。

***

## 💎 观点 1：一人成军——一夜验证十几个方向成为常态

> **"AI 自主提出假设、设计对照、推翻自己并写报告，人终于能把精力放在'问题值不值得问'上。"** ⭐⭐⭐⭐⭐

**传统研发节奏**：

```
想一个方向 → 写代码 → 跑实验 → 复盘 → 再想下一个
（一次 1 周起步，10 个方向 = 10 周）
```

**一人成军的新节奏**：

```
想 10 个方向 → AI 各自假设/对照/推翻/写报告
（一夜完成，人第二天只读 10 份报告，挑 1-2 个真问题深挖）
```

**为什么这是"研发范式跃迁"**：

| 维度 | 传统 | 一人成军 |
|---|---|---|
| **单位时间探索** | 1 个方向 | 10-20 个方向 |
| **失败成本** | 1 周 | 1 晚（AI 试错速度 < 人纠错速度）|
| **人的精力分配** | 90% 写代码 + 10% 思考 | 10% 选方向 + 90% 思考 |
| **瓶颈** | 算力 + 人力 | **问题的质量** |

**我的连接：**

这正是我**在 PR #2343（matryoshka fix）**里实际感受到的——**我**没写一行核心代码**——**核心的"`inspect.signature` 防御"是 17 行——**但前提是**：**

1. 我先**判断**"这个问题值不值得修"（yes——影响所有 matryoshka 用户）
2. 我**写出**复现步骤和期望行为
3. AI 帮我跑了 5 个边界用例
4. 我**判断**"这个修复对不对"（看 diff、看测试、看行为）

**全程 90% 精力在"判断"**——**10% 在"动手"**——**这就是一人成军**。

***

## 💎 观点 2：反对意见是最好的燃料——4 模型群聊

> **"作者让 Fable 5、Sol 5.6、Kimi K3、DeepSeek 四个 Agent 组成'群聊'，立下规矩'独到见解优先于面面俱到'。"** ⭐⭐⭐⭐⭐

**最反直觉的 3 个细节**：

### ① 不是分工，是涌现

**表面上看 4 个 Agent 是分工**：
- Fable 5 → 写代码
- Sol 5.6 → 跑实验
- Kimi K3 → 查文档
- DeepSeek → 写报告

**实际上**——**作者从一开始就没指定谁干什么**——**"分工是涌现出来的"**——**谁先想出新观点，谁就带头**。

### ② 事实必须复核

**最精彩的一幕**：

> GPT-sol **复核掉** Fable 虚报的 **+0.000712 增益**——**这就是规矩的价值**——**不是"4 个 Agent 加起来更聪明"**——**是"4 个 Agent 互相挑刺"**。

### ③ 1+1+1+1 >> 4

**最终不是"单模型英雄主义"**——**是"化学反应"**：

```
Fable 5  提出 "地面反射" 假设
GPT-sol  验证后给 +0.000712
K3       从"天线增益"路线独立撞上同一机制
DeepSeek 把 3 份结论拼成报告
```

**如果只有 Fable 5 一个**——**+0.000712 就是终点**——**因为它不知道有"天线增益"路线**——**K3 撞上才让作者意识到"这是同一个机制"**。

**我的连接：**

我自己的 `opensource-merge` skill **本质就是这条原理的工程化**——**合并开源仓库到内部分支**——**不是"git pull"**——**是 4 个 AI Agent 互相挑刺**：

1. Agent A 拉 upstream
2. Agent B 看 diff 找冲突
3. Agent C 跑测试找回归
4. Agent D 写合入报告

**我做的事**——**就是"决定 4 个 Agent 哪个先带头"**。

***

## 💎 观点 3：墙不是尽头，是问题问错了

> **"复赛中段四个 AI 异口同声'到头了'，作者凭通信直觉抛出几个第一性问题，AI 立刻分头撞开新门。"** ⭐⭐⭐⭐⭐

**这是 6 个观点里我标注最高分的**——**为什么？**

**因为这戳中了所有 AI Agent 实践者最容易犯的错**：

```
AI 探索 99% → 撞墙 → "没有新东西了" → 停止
         ↑                             ↑
         这是 AI 的"诚实"               但墙的成因 = 问题问错了
```

**作者的解法**：

1. 4 个 AI 同时"到头"——**这是信号，不是终点**
2. 立刻**回到第一性问题**——"为什么增益要靠这个机制？"
3. 抛出**新假设**——"如果不靠这个机制，靠另一个呢？"
4. AI 立刻分头撞开新门

**AI 99% 的探索 + 人 1% 的灵光一闪**——**那 1% 起决定性作用**。

**我的连接：**

我学 AgentScope W2 那周——**撞过这面墙 3 次**：

- 第 1 次：读 ReAct 协议，4 小时后觉得"就是 prompt 循环，没什么"
- 第 2 次：读 tool 调度，觉得"就是函数调用"
- 第 3 次：读 state 持久化，**第一次**撞墙

**这面墙的成因是"我以为 agent 就是 prompt + tool + state"**——**但实际还有"memory 持久化" + "context 压缩" + "trace 追踪"**——**我换了个问题"agent 在多轮对话里到底存什么"**——**立刻打开新世界**。

**所以这句话我接受**——**AI 是好工人，但 AI 不是好架构师**——**架构问题，永远要人问**。

***

## 💎 观点 4：地面反射——被当噪声的路径

> **"初赛最大跃迁来自人的直觉。AI 能把假设算到尽头，换不换假设由人决定。"** ⭐⭐⭐⭐

**这一观点是观点 3 的具体案例**——**值得单独说**：

**初赛阶段**：
- 几乎所有队伍都在追"天线增益"路线
- AI 也只在这一路线上算
- 大家都在优化同一个方向——**典型的"局部最优陷阱"**

**作者团队的破局**：
- 一位队员看比赛现场的物理环境，**注意到"地面反射"**
- 这个反射**之前被当噪声**——**被 AI 算到 0.0001 量级扔掉了**
- 作者**反问 AI**——"如果我们不扔掉这个噪声呢？"
- AI 重新跑，**地面反射是初赛最大跃迁**

**这是一个 5 分钟的人为判断**——**但它赢了初赛**——**比"AI 跑 1000 次实验"还管用**。

**我的连接：**

**8 周 AgentScope 学习**——**最重要的洞察都不是"AI 算出来的"**——**是"人读源码读出来的"**——**8 大架构飞跃**——**6 大记忆实现**——**3 层回退**——**全是"人的问题"**：

- "为什么 v1.0 升级 v2.0 不直接改？"→ 答：Schema Cascade
- "为什么 dict 比 list 适合存 state？"→ 答：LRU + 序列化天然
- "为什么 100 < size < 25000 是个双限制？"→ 答：不是为了"性能"是为了"业务语义"

**这些都不是 AI 能算出来的**——**因为前提是"读 15600+ 行源码"**——**人才能问对问题**。

***

## 💎 观点 5：根手册治 Agent 失忆

> **"73 个会话用'1 份根手册 + 8 份二级文档'接力：安全锚、最强链路、官方事实、关闭边界、开放问题等。"** ⭐⭐⭐⭐⭐

**这是 6 个观点里最可工程化的一条**——**我直接照搬到自己的 AgentScope 8 周学习笔记里了**——**因为它解决了我一直踩的坑**：

### 我的痛点（学 AgentScope 时）

| 会话数 | 问题 |
|---|---|
| 会话 1-5 | 还能记着 W1 W2 学了什么 |
| 会话 6-10 | "我之前讨论过 ReAct 协议吗？" |
| 会话 11-15 | "W5 的工具实现到底怎么做的？" |
| 会话 16-20 | 完全失忆，只能从 blog 里找 |

**73 个会话 = 完全失忆**——**人脑装不下**。

### 冠军的解法

```
1 份根手册 (root manual)：
  - 安全锚     (什么不能做)
  - 最强链路   (当前最佳方案)
  - 官方事实   (引用的论文/数据)
  - 关闭边界   (已经验证不work的方向)
  - 开放问题   (待研究的)

8 份二级文档：
  - 4 个 Agent 各自的"思考风格笔记"
  - 4 个比赛阶段的"决策日志"
```

### 关键反句

> **"手册是共享事实底座，不是路线命令。"**
>
> **"怕的不是 Agent 不听话，而是太听话导致 73 次重复。"**

**翻译一下**：

| 反模式 | 正解 |
|---|---|
| 把"根手册"当 SOP 严格执行 | 把"根手册"当**事实共享层**——**让 Agent 自由推理**——**但不要重复发明轮子** |
| "Agent 必须按手册做" | "Agent 必须看手册，**但可以反驳手册**" |

**这是 Agent 治理的核心**——**比 ReAct 协议更底层**——**比 tool call 设计更难**。

**我的连接：**

我最近做的 `opensource-merge` skill **本质上就是"根手册 + 二级文档"**：

- 根手册 = `UPSTREAM_SYNC_GUIDE.md`（"如何 merge 开源到内部"的标准流程）
- 二级文档 = 4 个 skill prompt 各自的"领域知识"

**未来**——**如果有 20+ skill**——**我也要做"1 份根手册 + N 份二级文档"**——**否则 skill 之间会互相打架**。

***

## 💎 观点 6：稀缺的是"知道该对哪个答案不满意"

> **"两轮分水岭都来自人的领域经验（一个加法、一个减法），中间几乎所有工作由 AI 完成。"** ⭐⭐⭐⭐⭐

**这是 6 个观点的总结**——**也是最锋利的一句**：

> **"给 AI 自由但不给它定义'成功'的自由；让反对意见有入口；把孤立会话织成接力系统；关键时刻提供物理直觉。"**

**我翻译成 4 条工程原则**：

| 原则 | 落地 |
|---|---|
| **1. 给 AI 自由** | 4 个 Agent 群聊，分工涌现 |
| **2. 不给 AI 定义"成功"的自由** | "独到见解优先于面面俱到"（观点 2）|
| **3. 让反对意见有入口** | GPT-sol 复核掉 Fable 的 +0.000712（观点 2）|
| **4. 孤立会话织成接力系统** | 1 根手册 + 8 二级文档（观点 5）|
| **5. 关键时刻提供物理直觉** | 地面反射路径（观点 4）|

**这 5 条**——**就是 AI 时代"人"的核心价值**。

***

## 🧭 总结：3 句话给读者

### 1. 算法竞赛层面

> **"AI 接管执行，人接管判断。AI 把 10 个方向算到底，人只挑 1-2 个真问题。"**

**未来 5 年**——**AI 比赛会变成"人的比赛"**——**谁的判断力强，谁的 AI 团队就强**。

### 2. 工程实践层面

> **"AI Agent 不是产品，是队员。你要做的不是'做一个 agent'，是'管一支队伍'。"**

**5 大工程能力**——**全部对应 6 个观点**：

| 能力 | 对应观点 |
|---|---|
| **任务编排** | 观点 1（一人成军）|
| **多 Agent 协作** | 观点 2（群聊 + 复核）|
| **问题定义** | 观点 3（墙是问题问错了）|
| **领域直觉** | 观点 4（物理直觉 vs AI 算）|
| **知识管理** | 观点 5（根手册 + 二级文档）|

### 3. 个人成长层面

> **"稀缺的不再是谁算得快，而是知道该对哪个答案不满意。"**

**这是我 8 周 AgentScope 学习最大的体感**——**15600+ 行源码 + 43 篇笔记**——**真正教会我的**——**不是"AgentScope 怎么实现"**——**是"我应该问 AgentScope 什么"**。

## 💎 收尾金句（全场最后一句）

> **"近期沉迷前沿新一代 Agent 技术实践和探索。**
> **一边尝试重构无线，一边尝试重构自己——**
> **不做无益之事，何以悦有涯之生。"**

**3 层解读**：

| 句 | 表面 | 深层 |
|---|---|---|
| **重构无线** | 优化算法/系统 | 重塑工作方式（不是小修小补，是架构级重写）|
| **重构自己** | 技能升级 | 思维范式迭代（从"做事"到"定问题"）|
| **不做无益之事** | 拒绝低效 | 拒绝**"AI 时代最贵的稀缺"被浪费**（观点 6）|
| **何以悦有涯之生** | 个人爱好 | **"知道自己为什么做"比"做得多快"重要** |

**这句话回答了整场分享的"为什么"**——**6 个观点是"怎么做"——这一句是"为什么"**——**没有这一句，6 个观点是技术报告**——**有了这一句，是工程师的人生选择**。

***

> **我接住这句**——
> **"重构无线 + 重构自己"——这是算法工程师的"心 × 行"**。
> **"心"是对前沿 Agent 技术的沉迷**——
> **"行"是把每一场分享、每一行源码、每一次复盘**——
> **都变成"重构自己"的素材**。
> **未来 5 年，"重构自己"的速度 = 职业天花板**。
