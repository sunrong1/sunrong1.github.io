# 第一层：日常工作方法论（10 条）

肖总说：**"每天是处理信息、处理输入、思考、安排工作"**。

## 1.1 核心观点

```
【普通员工】
- 做事 = 完成分配的任务
- 目标是"做完"
- 时间被任务填满

【肖总的认知】
- 做事 = 处理信息 + 处理输入 + 思考 + 安排
- 目标是"做对"
- 时间被"判断"填满
```

## 1.2 10 条日常工作法则

### 法则 1：处理信息

```
【错误】
- 每天处理"任务清单"
- = 被动执行

【正确】
- 每天处理"信息流"
- 猎头信息、行业信息、技术信息
- = 主动判断
```

### 法则 2：处理输入

```
【错误】
- 学完就忘
- 看了就用

【正确】
- 处理"输入" = 转化为"自己的东西"
- LeetCode 每天 1 题 = 输入
- 每天 1 题的复盘 = 处理输入
```

### 法则 3：思考

```
【错误】
- 埋头干活
- 不思考

【正确】
- 每天问"方向对吗"
- 每天问"方法对吗"
- 每天问"自己在什么位置"
```

### 法则 4：安排工作

```
【错误】
- 被任务推着走
- 来什么做什么

【正确】
- 主动安排"优先级"
- 哪些事重要、哪些紧急
- 哪些事不做的勇气
```

### 法则 5：时间节点

```
【错误】
- "我尽快"
- 没明确时间

【正确】
- 8 月准备 + 9 月投递 + 10 月面试 + 11 月 offer
- 每个节点有明确产出
- = 可控
```

### 法则 6：自己的节骤

```
【错误】
- 被主管 / 同事带节奏
- 被动应对

【正确】
- 自己的节奏 = 每天 1 题 + 每天 2 投递 + 每天 1 复盘
- 不被打乱 = 持续
```

### 法则 7：防止被打乱

```
【现实】
- 主管找你沟通绩效 = 被打乱
- 焦虑 / 情绪 = 被打乱
- 突发事情 = 被打乱

【应对】
- 被打乱时 = 回到自己的节骤
- 不是"继续推进"
- 是"先暂停 + 再回来"
```

### 法则 8：及时汇报

```
【错误】
- 闷头干
- 不让人知道

【正确】
- 跟主管汇报"我在看外部机会"
- 跟猎头汇报"我的进度"
- 跟家人汇报"我的计划"
- = 信息对称
```

### 法则 9：领导对齐

```
【错误】
- 自己想 = 自己干
- 不对齐预期

【正确】
- 跟主管对齐"他对我的预期"
- 跟猎头对齐"公司对我的需求"
- = 多方共赢
```

### 法则 10：知道怎么做最好

```
【错误】
- "差不多就行"
- 完成任务就好

【正确】
- 每天问"怎么做最好"
- 每天找"最优解"
- = 持续进步
```

## 1.3 应用到我当前的升级

```
【每天 30 min 复盘 - 应用肖总】
1. 处理信息：今天收到什么猎头 / 公司信息
2. 处理输入：今天学到了什么新东西
3. 思考：方向对吗
4. 安排工作：明天做什么
5. 时间节点：这周的里程碑是什么
6. 自己的节骤：我的节奏是什么
7. 防止被打乱：今天被打乱了吗
8. 及时汇报：谁需要知道我的进展
9. 领导对齐：我跟谁对齐了
10. 知道怎么做最好：今天有最优解吗
```

# 第二层：年度目标 + 成就感方法论（6 条）

肖总说：**"每年要有目标，可以获得成就感，要有自己的突破和成长"**。

## 2.1 核心观点

```
【错误的成长观】
- 涨薪 = 成长
- 升级 = 成长
- 加 title = 成长

【正确的成长观】
- 目标达成 = 成就感
- 能力突破 = 成长
- 选择有成就感的领域
```

## 2.2 6 条年度成长法则

### 法则 1：每年要有目标

```
【不是】
- "过一天算一天"
- "今年就这样"

【是】
- 2026 下半年目标：升级成功
- 2027 上半年目标：新公司立足
- = 明确、可衡量
```

### 法则 2：获得成就感

```
【错误】
- 一切向钱看
- "钱多就是好工作"

【正确】
- 什么让我有成就感
- 智能硬件 + AI 测试 = 我感兴趣
- 团队管理 + AI 转型 = 我能做好
- = 内在驱动
```

### 法则 3：突破和成长

```
【错误】
- 原地踏步 = 安全
- 待在舒适区

【正确】
- 突破 = 新的能力
- 成长 = 新的领域
- = 跳出舒适区
```

### 法则 4：选择有成就感的领域

```
【错误】
- "什么赚钱做什么"
- 跟随热门

【正确】
- "我感兴趣 + 能做好 + 有成就感"
- 智能硬件 + AI 测试 = 我感兴趣
- = 长期主义
```

### 法则 5：每个领域都有自己的算法

```
【错误】
- "只有某些领域有价值"
- "我转 AI 是不是晚了"

【正确】
- 测试架构师有算法
- AI 应用有算法
- Harness 工程师有算法
- 每个领域深耕 = 都大有可为
- = 没有"夕阳领域"
```

### 法则 6：大有可为

```
【错误】
- "35+ 没机会了"
- "传统行业没前景"

【正确】
- 36 岁不是"太晚"
- 智能硬件 AI 测试 = 早期
- 团队管理 + AI = 大有可为
- = 信心
```

## 2.3 应用到我的升级

```
【2026 下半年目标】
- 升级成功（最晚 11 月拿 offer）
- 薪资涨幅 50%+（47K → 80K+）
- 新平台 = 智能硬件 + AI 测试

【成就感来源】
- 智能硬件 AI 测试领域 = 感兴趣
- 团队管理 + AI 转型 = 能做好
- 不是"为了钱"

【突破点】
- 从硬件到 AI = 突破
- 从单一公司到新平台 = 突破
- 从小组长到 Leader = 突破
```

# 第三层：成为专家的关键（5 条）— 肖总核心洞察

肖总说：**"成为专家一定要有自己的领域或者作品，别人一说，就会想到你"**。

## 3.1 核心观点

```
【普通员工】
- "我做过很多项目"
- "我什么都会"
- = 没有标签

【专家】
- "我是 X 领域的专家"
- "一说到 X 就想到我"
- = 个人品牌
```

## 3.2 5 条专家立身法则

### 法则 1：有自己的领域或作品

```
【不是】
- 什么都做
- 没方向

【是】
- 有清晰的领域定位
- 有可展示的作品
- = 个人品牌的基础
```

### 法则 2：别人一说，就会想到你

```
【不是】
- "做硬件的 + 做 AI 的 + 做测试的"
- = 没有记忆点

【是】
- "dave = 智能硬件 AI 测试"
- "dave = 自动化测试平台 + 团队管理"
- = 一听就想到
```

### 法则 3：强调客户价值

```
【不是】
- "我做了什么"
- 技术视角

【是】
- "客户获得了什么"
- 价值视角
```

### 法则 4：强调公司价值

```
【不是】
- "完成 KPI"
- "做完任务"

【是】
- "帮公司省了多少钱"
- "帮公司提升多少效率"
- = 公司视角
```

### 法则 5：强调团队价值

```
【不是】
- "我做了 X"
- 个人视角

【是】
- "我帮团队做了什么"
- "我培养了谁"
- "我解决了什么问题"
- = 团队视角
```

## 3.3 "3 个价值" = 价值创造的三角

```
        客户价值
          /\
         /  \
        /    \
       /      \
      /________\
 团队价值 —— 公司价值

【核心】
- 不是"单一价值"
- 是"三角价值"
- 客户 + 公司 + 团队 = 三位一体
- 任何一边缺 = 价值不完整
```

## 3.4 应用到我的升级

### 应用 1：定位我的"领域"

```
【我的领域】
- 智能硬件 + AI 测试 = 主标签
- 自动化测试平台 + 团队管理 = 副标签
- 11 年硬件测试经验 + 5 年 AI 转型 = 资历标签

【一句话定位】
"我是dave，11 年硬件测试经验测试架构师，3 年 AI 转型，
专注于智能硬件 + AI 测试这个领域。"
```

### 应用 2：定位我的"作品"

```
【作品 1】自动化测试平台
- 覆盖核心场景 85%
- 节省人力 40%
- 团队 5-10 人使用

【作品 2】AI 超自动化项目
- 测试用例生成准确率 60% → 85%
- 节省人力 40%
- 团队 5 人

【作品 3】14 篇论文 + 105 篇博客
- 输出能力
- 持续学习
```

### 应用 3：每个作品突出"3 个价值"

```
【自动化测试平台】
- 客户价值：交付周期从 X 缩短到 Y
- 公司价值：覆盖从 30% 提升到 85%，节省成本 Z
- 团队价值：标准化让新人上手从 2 月到 2 周

【AI 超自动化项目】
- 客户价值：测试准确率从 60% 提升到 85%
- 公司价值：节省人力 40%，约 X 万/年
- 团队价值：带 5 人，培养 2 名核心工程师
```

# 第五层：应用到升级的具体策略

## 5.1 简历：用"3 个价值"改造每个项目

```
【错误简历】
"负责自动化测试平台的设计与开发，
包括 X 模块、Y 功能、Z 架构。"

【正确简历】
"自动化测试平台 | 客户价值 X | 公司价值 Y | 团队价值 Z
- 客户价值：交付周期缩短 50%，客户满意度提升
- 公司价值：测试覆盖从 30% 提升到 85%，节省人力 40%
- 团队价值：标准化让新人上手从 2 月缩短到 2 周
- 技术栈：Python + Vue + PostgreSQL"
```

## 5.2 自我介绍：突出"领域 + 3 个价值"

```
【错误自我介绍】
"我是dave，11 年 XX 经验，做过自动化测试平台。"

【正确自我介绍】
"我是dave，11 年硬件测试经验测试架构师，3 年 AI 转型。
我的工作直接产生 3 个价值：
1. 客户价值：交付周期缩短 50%
2. 公司价值：覆盖提升到 85%，节省成本 X 万
3. 团队价值：带 10 人团队，培养 5 名核心成员

我专注于智能硬件 + AI 测试这个领域。
我希望找到一个能继续创造这 3 个价值的平台。"
```

## 5.3 项目讲解：STAR + 3 个价值

```
【S（情境）】
"客户反馈测试周期太长，影响产品上市。"

【T（任务）】
"我负责缩短测试周期。"

【A（行动）】
"我主导设计并实现了 X 自动化测试平台。
- 客户维度：跟客户对齐需求
- 公司维度：覆盖核心场景 85%
- 团队维度：标准化让新人快速上手"

【R（结果）】
"最终产生 3 个价值：
1. 客户价值：交付周期 -50%
2. 公司价值：节省成本 X 万
3. 团队价值：培养 5 名核心成员"
```

## 5.4 反问面试官：展现"价值视角"

```
【错误反问】
"请问团队有多大？技术栈用什么？"

【正确反问】
"请问贵公司在 [业务] 方向上的客户群是什么？
我希望找到一个能直接产生客户价值的平台。"

【更深】
"您觉得这个岗位上最重要的是什么？
是技术深度、客户理解，还是团队管理？"
```

## 5.5 选择 offer：用"3 个价值"评估

```
【错误评估】
- 薪资高就选
- Title 高就选

【正确评估】
- 这个平台能创造客户价值吗？
- 这个平台能创造公司价值吗？
- 这个平台能创造团队价值吗？
- 3 个价值都符合 = 值得去
- 1-2 个符合 = 谨慎
- 0 个符合 = 不去
```
