# QCC 基础：小组、角色、程序与工具

QCC（Quality Control Circle，质量控制小组）是日本石川馨 1962 年提出的结构，在中国从 1978 年北京内燃机总厂建起第一个 QC 小组算起，已经跑了四十多年。

上一篇写的是**怎么用** —— 改进做完为什么会反弹、三个关口怎么过。这篇补另一半：**这套机制由哪些零件组成、每个零件管什么、哪些是硬规则。**

## 什么时候你会需要了解这些

四种挺常见的处境：

| 你的处境 | 你真正需要知道的 |
|---|---|
| 公司推 QCC，让你去当圈长 | 注册怎么走、评审卡在哪、半年周期怎么算 |
| 你是管理者，要给团队做一次 QCC 培训 | 它由哪几块组成，缺一块会怎样 |
| 同事在用这套流程，你搞不懂他在干什么 | 每个环节在解决什么问题 |
| 你不打算叫它 QCC，只想借用「小组 + PDCA + 固化」这套结构 | 骨架在哪，边界在哪 |

⭐ 这四种处境要的不是「QC 是什么」。

要的是**「这套东西由哪些零件组成、每个零件管什么、哪些是硬规则、哪些可以按自己情况调」**。

搞清这个，你既能当圈长，也能自己搭一套改进流程。

## 一、一个 QC 小组的完整生命周期

先看全貌。这是一套流程，不是一个活动 —— 从建组到成果固化，每个环节都有明确的产出物和卡点。

![一个 QC 小组的完整生命周期](/images/qcc-lifecycle.png)

### 三个角色

| 角色 | 干什么 |
|---|---|
| **圈长** | 需要思维与分析问题能力、沟通与协调能力 |
| **辅导员** | 提供改进知识、工具与方法支持 |
| **圈员** | 立足本职工作，参与分析与实施 |

**人数 3-10 人。** 部分企业规定 3-7 人，机械工业协会的说法是 4-10 人为宜。

⭐ 有一条常被记错：**一个人可以同时参加多个 QC 小组。** 真正的限制是「立足本职工作」—— 课题要来自你本岗位现场的问题，不是你随便挑个好做的题拉几个人凑数。

### 三种组建程序

| 程序 | 谁定题 | 谁定人 | 特点 |
|---|---|---|---|
| **自下而上** | 小组自己找 | 小组自己选 | 积极性最高，日本典型模式 |
| **自上而下** | 上级指派 | 上级配 | 中国企业最普遍 |
| **上下结合** | 上级给范围 | 上下协商 | 官方推荐，取两者之长 |

「上下结合」为什么被推荐：自下而上容易选小问题、自上而下容易选到没人关心的硬骨头。**上下结合 = 上级给一个够大的范围，小组自己在里面挑。**

### 两个注册，别搞混

- **小组注册** —— 每年一次。停活动超过半年，注销。
- **课题注册** —— 每个课题开展前注册。

一个小组一年可以跑好几个课题，每个课题单独注册。**两个注册管的是不同东西** —— 小组注册管资格，课题注册管这次改动的合法性。

## 二、深入：几个关键零件

### 它到底是什么

中国质量协会《质量管理小组活动准则》（TCAQ10201-2020）的标准定义：

> 由生产、服务及管理等工作岗位的员工**自愿结合**，围绕组织的经营战略、方针目标和现场存在的问题，以改进质量、降低消耗、改善环境、提高人的素质和经济效益为目的，运用质量管理理论和方法开展活动的团队。

拆开看，**定义里有三个不能少的词**：

**自愿结合** —— 不是上级派的。

**现场存在的问题** —— 不是行业趋势、不是战略课题。

**运用质量管理理论和方法** —— 不是开会讨论。

前两条决定了这个机制能不能活，第三条决定它是不是走过场。

### 从日本到中国

| 时间 | 事件 |
|---|---|
| 1950s | 日本出现「现场 QC 讨论会」 |
| 1962 | 石川馨正式提出 QC 小组；第一个注册的是日本电电公社松山搬运机 QC 小组 |
| 1976 | 首届世界 QC 小组大会（东京） |
| 1978.09 | 北京内燃机总厂建立**中国第一个 QC 小组** |
| 1978.12 | 一机部认定全国机械工业 4277 个班组为「质量信得过班组」 |
| 1979 | 第一次全国 QC 小组代表会议在北京召开 |
| 1981.09 | 一机部首次「双代会」（质量信得过班组 + 质量管理小组成果发表会），此后成为年度惯例 |
| 1990s | 日科技连关东支部完成「课题达成型 QC STORY」程序 |
| 1996.05 | 第二次修订「QCC 纲领」，改名「QCC 的基本」 |
| 2000 | 中国质协等四单位（质协 / 科协 / 共青团 / 全总）提出**创新型课题** QC 活动 |

⚠️ 中国的「创新型课题」是**在学习总结日本「课题达成型」基础上形成的** —— 这两个术语对应的是同一个东西。

### 四大特点，这是 QCC 的身份证

| 特点 | 含义 |
|---|---|
| **自主性** | 自愿参加，自我管理，自我教育 |
| **群众性** | 以一线操作者为主，不只是干部和技术骨干 |
| **民主性** | 组长可民主推选、可轮流担任；讨论不分职位与技术高低 |
| **科学性** | 按科学程序推进，用数据说话，不靠「想当然」或个人经验 |

⭐ **自主性是命门。**

一旦变成「上面派下来的任务」，自主性就没了，剩下的只是执行 —— 而执行型改进不需要 QCC，用项目管理就行。

这也是为什么这篇开头那张「什么时候你会需要了解这些」的表里，第一行写的是「公司推 QCC，让你去当圈长」：**被指派的人当圈长，和自己想组个圈的人当圈长，做出来的东西完全是两回事。**

### 课题分类：三个独立维度

这块最容易记混。QCC 的课题分类是**三维并列**，不是一个三维树：

```
按活动性质（最常用的一级分类）
├── 问题解决型 → 现场型 / 服务型 / 攻关型 / 管理型
└── 课题达成型（= 创新型）→ 达成新目标

按目标来源
├── 自定目标课题
└── 指令性目标课题（上级下达或直接选考核指标）

按问题性质
└── 品质改善 / 效率提升 / 成本降低 / 安全保障
```

⚠️ **「课题达成型」不等于「指令性目标课题」。**

前者按**活动性质**分，后者按**目标来源**分，是两个并列维度。一个课题可以是「课题达成型 + 自定目标」，也可以是「课题达成型 + 指令性目标」。

两种类型的核心差异在这里：

![问题解决型 vs 课题达成型](/images/qcc-two-types.png)

一句话记：**问题解决型从「不良程度」切入，有历史数据，必须做原因分析；课题达成型从「更好程度」切入，没有历史数据，不做现状调查也不做原因分析**，改成「提出各种方案并确定最正确方案」。

### 工具全景

![QCC 的工具全景](/images/qcc-tools-panorama.png)

**石川馨的 QC 七大工具**：流程图 · 检查表 · 帕累托图 · 特性要因图（鱼骨图）· **管理图 / 控制图** · 散布图 · 直方图

七个全是数据类工具，共同点是「用数据说话」—— 这是 QCC 科学性的底座。

**进阶与辅助手法**（不在七大工具内，但原因分析和方案生成离不开）：头脑风暴 · 关联图 · 层别法 · 亲和图 · 系统图（树图）· PDPC 法 · 正交试验

**两个骨架**：

- **5M1E**（Man / Machine / Material / Method / Environment / Measurement）—— 原因分析的鱼骨图骨架
- **5W1H**（What / Why / Who / Where / When / How）—— 对策表的填写骨架

⭐ 工具不是越多越好，**关键是别拿错工具干错活**。原因分析用鱼骨图、效果确认用柏拉图，都是有对应关系的。用鱼骨图去找多个问题的交叉原因，结果就是一堆分不清主次的箭头。

### 和 6Sigma / TOPN 的分界

这两套经常被放一起比，但**分界不在方向，在驱动源**。

| | 6Sigma / TOPN | QCC |
|---|---|---|
| **驱动源** | 组织授权 + 黑带方法论 | 现场人员 + 自主发现问题 |
| **问题来源** | 假设（数据驱动，DMAIC） | 现场（问题驱动，PDCA） |
| **组织形态** | 项目制，有期限 | 小组制，长期存在 |
| **人的角色** | 专家主导 | 一线主导 |

6Sigma 是**组织从上往下派项目**，QCC 是**现场自己往上提问题**。所以 6Sigma 的人通常在中台，QCC 的人通常在产线。

如果一个改进是「公司定了要降本 10%，各厂组团队来做」，那是 6Sigma 的味道。如果是「注塑车间发现某批不良率高，组了个圈查为什么」，那是 QCC。

### 两个最常见的病

**虎头蛇尾** —— 一哄而起，然后沉寂。

这是最常见的死法：立项时热情很高，两个月后小组会开不起来了，因为**改进没有跟激励、资源、考核挂上**，只靠初始热情撑着。

**走过场（假数据）** —— 开会认真，数据编的。

评审时重点查两件事：**数据有没有捏造**、**是不是组长一个人包办**。

这两个病都出在同一个地方：机制里的**强制节点**被跳过了。没有评审节点，就没人拦得住走过场；没有注册和周期约束，就拦不住虎头蛇尾。

## 三、怎么判断一个团队是真的在跑 QCC

不看 PPT，不看成果汇编。看四件事：

**有没有一个跨岗位的小组** —— 三个人的部门内会是「碰头会」，不是 QC 小组。群众性这条一测就知道。

**小组注册和课题注册是不是分开的** —— 只注册小组、课题随便做，说明流程只走了一半。

**评审是不是真在卡人** —— 真评审会打回。没被打回过的评审不是评审。

**改进有没有写进某份标准文件** —— 这条最关键，也是最常被跳过的。**没写进标准的改进，成果一定反弹。**

## 一点补充

有几个概念常被混着说，顺手厘清：

**PDCA ≠ 严格意义上的「戴明环」。**

戴明环 1950 年在日本 JUSE 诞生；PDCA 是日本质量界的命名（据今井正明考证）；石川馨 1962 年引入 QCC。戴明本人在 1986 年批评 PDCA 是「corruption PDCA」，主张改回 PDSA。

讲 PDCA 不会错，讲「戴明环 = PDSA」才显专业。

## 最后

这套机制最值得学的地方，是它把**「改进」从一次性项目变成了一个持续的循环**。

每个课题结束都会问一句：**下一个课题是什么？** 一个能持续转的小组，比一次漂亮的质量攻关有价值得多。

而它能转下去的全部理由，就一句话：

> **改进做完了，但要写进某份标准，才算真的做完。**
