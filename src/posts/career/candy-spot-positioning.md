# 甜点职业定位：ISTJ + AI 时代的 3 个生态位

> **核心问题**：我应该投什么岗位？
>
> **我的答案**：不是"投什么岗位"，而是"成为什么角色"。
>
> 这篇文章总结我几十天来最专业的自我认知升级——把 3 个老岗位重命名为 3 个新生态位。

<!-- more -->

## 一、引言：从迷茫到 3 个甜点

过去几十天，我一直在思考一个核心问题：**"AI 时代，什么岗位最匹配我？"**

我尝试过很多答案：
- AI Agent 开发工程师
- 智能硬件测试架构师
- AI 研发效能工程师
- 测试开发工程师

但这些答案都有问题——**它们都太泛，HR 不知道你到底能做什么**。

直到 9-20 那天，我重新整理自己的证据：
- 长期"为硬件写软件"实战（10+ 年量级）
- AI 转型积累
- 多个生产项目主导
- 多次开源贡献
- 数十篇技术博客

我突然意识到：**问题不是我"该投什么岗位"，而是"市场对每个岗位的真实期待是什么 + 我到底在哪个领域像玩"**。

这就是"甜点"思维的起源。

---

## 二、为什么需要"甜点"思维？

### 2.1 传统求职的陷阱

大多数人求职的方式是：
1. 看 JD
2. 匹配关键词
3. 投递
4. 等回应

这个流程最大的问题：**你是在追岗位，不是定位自己**。

结果：
- 投了 100 份简历，0 回应
- 面试 10 场，被"经验不匹配"刷掉
- 即使拿到 offer，干 3 个月发现不合适

### 2.2 甜点思维

甜点思维 = **"我知道我是什么 + 我知道市场在哪"**。

具体来说：
- 我是什么 = 我的性格（ISTJ）+ 我的能力（生产化 / 治理 / 质量）+ 我的兴趣（建系统）
- 市场在哪 = 哪些岗位匹配"我的画像"
- 甜点 = **两者交集**

甜点思维的好处：
- **不被岗位牵着走**：我知道自己要成为什么，岗位只是路径
- **避开烂 offer**：面试时主动反问，筛选掉不合适的
- **长期发展**：甜点是 3-5 年的方向，不是 1 年的过渡

---

## 三、重新定义 3 个方向

我最初拟定了 3 个方向，但分析后发现**市场对它们的期待差别很大**。

| 方向 | 匹配度 | 画像 | 主要风险 | 建议精准命名 |
|------|:-----:|------|---------|------------|
| AI Agent 开发工程师 | 7/10 | 编排、工具调用、可靠性、多 Agent | 太泛，容易被当成 Prompt/框架/算法/Demo 岗 | **AI Agent 生产化 / Harness / AgentOps** |
| AI 研发效能工程师 | **9/10** | 建平台、定标准、自动化、可审计、可复用 | 容易变成内部工具打杂、行政推动、催进度 | **AI 研发效能 / DevEx / AI Enablement** |
| AI 测试开发工程师 | 7.5/10 | 质量门禁、评估、回归、审计、可回退 | 传统测开偏手工、UI 自动化、外包、KPI | **AI 质量 / LLM 评估 / Agent 测试架构** |

**结论**：
- **AI 研发效能** 最像我的"玩"，最匹配 ISTJ
- **AI Agent 开发** 是增长赛道，但必须加限定词：生产化、Harness、AgentOps
- **AI 测试开发** 是隐藏金矿，但传统测开是坑；要升级成 AI 质量与评估

## 四、方向一：AI Agent 生产化 / Harness 工程师

### 4.1 一句话定位

**不让 Agent 更聪明，而是让 Agent 在生产里活下去。**

### 4.2 为什么适合 ISTJ

我博客里写过：「Agent = Harness + Model」「Agent 在生产里翻车，99% 不是 Model 的问题，是 Harness 没做对」。

这就是我的核心卖点。ISTJ 的**秩序感、边界感、可回退、可审计**，正好是 Harness 工程的核心。

### 4.3 日常任务

- Agent 状态机、工具调用、重试、回滚、检查点
- 权限、审计、可观测性、评估门禁
- 多 Agent 编排、生产部署、故障复盘
- 把方法论（如 BMAD-METHOD）落成可执行流程

### 4.4 搜索关键词

```
AgentOps · AI Agent Infrastructure · Harness Engineer
LLMOps · Agent Reliability · Production AI · AI Agent Platform
```

### 4.5 简历钩子

- 多个存量项目 AI 重构全流程
- Agent = Harness + Model（核心观点）
- 文档分片、过程可中断、关键决策人工检查点

### 4.6 避坑

❌ 岗位天天写 Prompt、调模型、追 SOTA、做 Demo，**不去**。

## 五、方向二：AI 研发效能 / AI Coding Enablement / DevEx 平台工程师

### 5.1 一句话定位

**让团队用 AI 编码不翻车，把 AI Coding 变成可审计、可回退、可复制的工程能力。**

### 5.2 为什么适合 ISTJ

**这是我最像玩的岗位**（9/10 匹配）。

ISTJ 喜欢：
- 建标准
- 建平台
- 建黄金路径
- 建质量门禁

这些全是研发效能的核心。

### 5.3 日常任务

- AI 编码助手接入团队：代码审查、CI/CD、测试门禁
- 规范、权限、审计、回滚机制
- 内部开发者平台、黄金路径、模板、自动化
- 让 AI 产出可维护、可验证、可交接

### 5.4 搜索关键词

```
Developer Productivity · DevEx · Platform Engineering
AI Enablement · AI Coding Governance · Engineering Productivity
研发效能 · 研发平台
```

### 5.5 简历钩子

- "AI Coding 不是用 AI 写代码，是给 AI 建一套 Harness"
- 多个存量项目 AI 重构的工程纪律
- 多 Agent 架构与方法论落地

### 5.6 避坑

❌ 如果岗位是"效能运营"、催进度、做报表、推行政任务，**不去**。

你要的是**架构权限和平台建设**。

---

## 六、方向三：AI 质量与评估架构师 / Agent 测试架构师

### 6.1 一句话定位

**AI 越强，越需要验证它没胡说、Agent 没跑偏。**

### 6.2 为什么适合 ISTJ

这是测试开发的升级版。ISTJ 的内建品管系统、合规敏感、边界意识、可审计偏好，在这里是优势。

你关心的不是"能不能跑"，而是"上线后会不会出事"。

### 6.3 日常任务

- LLM 评估集、回归测试、红队、质量门禁
- Agent 轨迹测试、工具调用正确性、行为审计
- 生产监控、可观测性、异常回滚
- AI 治理、权限、数据边界、合规

### 6.4 搜索关键词

```
LLM Evaluation · AI Quality Engineer · AI Test Architect
Agent Testing · AI Governance · AI Red Teaming
AI 质量工程 · 测试架构师
```

### 6.5 简历钩子

- 关键决策人工检查点
- 生产级约束、可审计、可回退
- 存量项目 AI 重构中的质量保障

### 6.6 避坑

❌ 传统点点点、UI 自动化、外包测试、纯手工用例，**不去**。

## 七、最佳组合定位

不要只写"AI Agent 开发工程师"。可以写成：

> **AI Agent 生产化 / AI 研发效能 / AI 质量工程方向**：专注把 AI Coding 与 Agent 从 Demo 变成**可审计、可回退、可复制的工程系统**。

搜索时组合这些词：
- AI Agent 生产化、AgentOps、Harness 工程
- AI 研发效能、DevEx、AI Enablement、平台工程
- LLM 评估、AI 质量、Agent 测试架构、AI 治理

## 八、面试 4 个反问（排除烂 offer）

投递简历只是开始，**面试才是真正的"双向选择"**。以下 4 个反问可以帮你排除 80% 的烂 offer：

1. **团队在 Demo 阶段还是生产阶段？**
   - Demo 阶段 = 学不到生产化能力
   - 生产阶段 = 真正的甜点

2. **有没有 Harness、评估、回滚机制？**
   - 没有 = 公司不重视 AgentOps
   - 有 = 你的能力能落地

3. **我有没有权限建标准、建平台？**
   - 没有权限 = 你是工具人
   - 有权限 = 你是架构师

4. **日常多少时间在救火、扯皮、追需求？**
   - 救火 > 50% = 别去
   - 救火 < 30% = 甜点

## 九、备选交叉方向

**遗留系统 AI 现代化架构师**

你的存量项目 AI 重构经验，在这个方向很稀缺，可以作为差异化加分项。

特点：
- 大量传统企业、银行、政府 = 钱多、强度低
- "老系统 + AI" = 长期 5-10 年市场
- 你有 C#/.NET 等存量项目实战 = 真实证据

搜索关键词：
- 遗留系统 AI 化
- Legacy Modernization with AI
- 传统系统 AI 升级
- 企业架构 AI 化
